# خطة تطوير No One Home

**Pottsfield Studio** · الإصدار 0.1 · 2026-11-21 · [GDD](GDD.md)

> هذه الخطة تحلّ محل خطة Flannan Light (محفوظة في فرع `archive/flannan-light-v1`). خط الإنتاج التقني كما هو، والتغيير في القصة والشكل والسياق والاسم فقط. الأرقام المعلّمة بـ [تقدير] نؤكدها بالقياس على هاتفك (Redmi Note 14، Helio G99 Ultra).

## 1. القرارات التقنية

| القرار | الاختيار | السبب |
|---|---|---|
| المحرك | Godot 4.7.2 + GDScript (باقٍ) | Unreal بلا تصدير ويب، ولا يُبنى في الحاوية السحابية ولا في CI المجاني، ولكل اختبار APK يُثبَّت يدوياً. Godot يعطيك رابطاً حياً لكل دفعة |
| المُصيِّر | Compatibility (ويب) | الوحيد المتاح للويب. بلا SSAO/SSR/GI، لذلك نعوّض بالإضاءة اليدوية والخامات الممسوحة |
| الأسلوب البصري | 3D بارتفاع قابل للتغيير (360 / 480 / **540** / 720 / 1080) ثم تكبير خطي وشيدر فيلم: تدرج لوني، حبيبات، vignette، انحراف لوني خفيف، توهّج | بدل البكسل المنخفض و dither القديم. ارتفاع 540 افتراضي ونقيسه عندك |
| الخامات | PBR ممسوحة من ambientCG (CC0): جدار، جدار رطب، أرضيات، بلاط، سقف، قماش، خشب (Albedo + Normal) | واقعية فوتوغرافية بتكلفة صغيرة. UV بالأمتار تُكتب مباشرة، بلا triplanar |
| ضغط الخامات | ETC2/ASTC للموبايل في التصدير | بدونه تنهار ذاكرة المتصفح على Mali-G57 |
| الإضاءة | مصابيح Omni لكل غرفة بلا ظلّ افتراضياً، مع طبقات رؤية (visual layers) تمنع تسرّب ضوء الغرفة إلى الغرف المجاورة | الإضاءة يجب أن تنطفئ لحظياً (مشاهد انقطاع النور). الظلال اختيارية: ممر فقط / كل المصابيح |
| الإضاءة غير المباشرة | لاحقاً: خَبز في Blender (Cycles، بدون GPU) إلى خامات UV2 للإضاءة غير المباشرة فقط، مع مصباح ديناميكي واحد لكل غرفة | يجمع الجودة الفوتوغرافية مع إمكانية الإطفاء |
| الشقة | تُبنى بالكود من صناديق (`apartment.gd`) بوجوه لكل منها مادة وطبقة | تكرار سريع ومعايير اختبار آلية |
| النماذج لاحقاً | Blender عبر bpy (سكربتات في `tools/blender`) والملفات المولّدة تُرفع في المستودع | كما في المشروع السابق |
| الواجهة | تُرسم بالدقة الكاملة فوق العالم | نصوص مقروءة وأزرار لمس مريحة |
| الأيام | كل يوم ملف `DayData` (مهام، أحداث، مستندات، مكالمات) | التصعيد يصبح كتابة محتوى لا برمجة |
| الحفظ | تلقائي عند النوم في `user://` | يعمل على الويب (IndexedDB) والأندرويد |
| النص | إنجليزي داخل اللعبة، وجدول ترجمة من البداية | إضافة لغة بلا تعديل كود |
| الاختبار | اختبارات GDScript headless في CI: المواد، الأبواب، الإضاءة، المشي عبر الممر، الجدران والأبواب المغلقة | حماية البناء قبل كل نشر |

**ميزانية الأداء:** 30 إطاراً/ث ثابتة كحدّ أدنى على Redmi Note 14 (ويب)، ≤100 draw call (الحالي 35–85 حسب الموضع)، ≤50 ألف مثلث (الحالي أقل من 4 آلاف)، حجم الويب ≤40 MB [تقدير]. نقيسها على هاتفك الحقيقي لا على المحاكي.

## 2. خط النشر (كما هو)

1. أدفع إلى `main` فيشغّل GitHub Actions: استيراد المشروع، اختبار smoke، تصدير Web (بلا threads)، نشر على GitHub Pages.
2. الملفات تحمل رقم البناء (`b<N>.html` …) كي لا يخلط الهاتف بين `.wasm` قديم و `.pck` جديد.
3. رقم البناء وcommit يظهران في القائمة الرئيسية.
4. زر Start يفتح الصوت ويطلب ملء الشاشة وقفل الوضع الأفقي.
5. APK/AAB يُبنى في المرحلة الأخيرة فقط.

**خطوة واحدة منك:** إعادة تسمية المستودع من Settings ← General ← Repository name (مثلاً `no-one-home`). بعدها يتغير رابط Pages إلى `https://mahmoud70004-debug.github.io/<الاسم الجديد>/` وأعيد ربط الجلسة.

## 3. المراحل ومعايير الإنجاز

### المرحلة 0: خط الإنتاج — **منجزة** (موروثة من المشروع السابق)

### المرحلة 1: تطوير الشكل (Look Dev) — **هذا البناء**
- الشقة كاملة بالصناديق: ممر 10.6 م، مطبخ + صالة، غرفة نوم، حمّام، غرفة أبي، خزانة، أبواب بمفصلات، نوافذ، مفاتيح إنارة، هاتف أرضي في آخر الممر.
- شيدر الفيلم + 4 ألوان (DAMP / COLD / SICKLY / RAW) وأزرار القياس على الشاشة: GRADE، RES (ارتفاع الصورة)، SHADOW، AA.
- **معايير الإنجاز:** تفتح الرابط على هاتفك، تقول أي RES يعطي 30 إطاراً ثابتة، وهل الممر والإضاءة والألوان "مقنعة ومقلقة". أضبط بعدها الخامات والأضواء من ملاحظاتك.
- **ما سيتغير بعدها:** الأثاث الآن صناديق بسيطة، تُستبدل بنماذج Blender مفصّلة في المرحلة 1b.

### المرحلة 1b: الأصول والإضاءة المخبوزة
- أثاث ونماذج Blender (أريكة، سرير، مطبخ، حمّام، علب) مع UV2.
- خَبز الإضاءة غير المباشرة وحفظها كخامات، وجدول مصابيح للإطفاء والوميض.
- **معايير الإنجاز:** نفس الأداء مع جودة أعلى بشكل ملحوظ.

### المرحلة 2: يوم 1 كامل
- نظام التفاعل والمهام، `Hud.say` لصوت مارتن الداخلي، الرسالة والمستندات، النوم والحفظ التلقائي، `DayData`.
- **معايير الإنجاز:** اليوم 1 يُنهى من الاستيقاظ إلى النوم، و"Continue" يعيد الحالة (اختبار آلي).

### المرحلة 3: المقطع العمودي (الأيام 1–4)
- الصوت: خطوات، سعال، ضحك، طرق (ملفات CC0 أو من إنتاجك، مع `AudioStreamPlayer3D`).
- مدير الهلاوس: أول أحداث، انطفاء المصابيح، الهاتف الأرضي.
- **الغريب (The stranger):** شخصية بشرية واحدة، حركة stop-motion بـ 12 إطاراً، لا تتحرك إلا خارج مجال الرؤية.
- **معايير الإنجاز:** لاعب جديد يصف الحدث الأول بأنه "مقلق" لا "محيّر".

## 4. مخاطر معروفة
- **جودة الويب:** سقف الواقعية في Compatibility أقل من Forward+. لذلك نعتمد الخَبز اليدوي والخامات.
- **ذاكرة الهاتف:** ممنوع إضافة خامات 2K بلا قياس؛ الخامات الحالية 1K وبعضها 512 بضغط ETC2/ASTC.
- **الشخصية البشرية والصوت:** تحتاجان مصدراً (ملفات CC0 أو صوتك أنت)، وأسألك عنهما في المرحلة 3.
